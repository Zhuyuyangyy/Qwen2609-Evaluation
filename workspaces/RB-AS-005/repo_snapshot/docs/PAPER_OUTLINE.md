## Abstract

Multi-agent LLM systems that chain tool calls introduce compositional security risks unaddressed by existing single-turn or single-agent defenses. We present ChainRisk, a formal framework that models agent behavior as directed acyclic graphs (behavior chain graphs), defines risk propagation semantics with dynamic attenuation, and enables runtime detection of emergent threats arising from agent-tool interactions. We evaluate on 200 independent test cases spanning 4 attack categories against 6 baseline methods. ChainRisk achieves [X]% detection rate with [Y]% false positive rate, outperforming all baselines. To our knowledge, this is the first formal treatment of compositional risk propagation in multi-agent tool-use systems.

## 1. Introduction

- **Problem statement:** Multi-agent systems (AutoGPT, CrewAI, LangGraph) compose tools across agents; each tool is safe in isolation but the chain creates emergent risk
- **Core insight:** Security is not compositional -- safe(A) + safe(B) != safe(A -> B)
- **Motivating example:** Agent A reads file -> Agent B summarizes -> Agent C sends email = data exfiltration, none of the individual steps are malicious
- **Research questions:**
  - RQ1: How to formally model risk propagation across agent tool chains?
  - RQ2: How to detect compositional threats at runtime with bounded overhead?
  - RQ3: How does dynamic risk attenuation improve precision over static analysis?
- **Contributions:**
  1. Formal model: behavior chain graph (BCG) with risk propagation semantics
  2. Dynamic attenuation mechanism for risk scoring across chain depth
  3. Runtime detection algorithm with O(n log n) complexity
  4. Evaluation on 200 cases, 6-method comparison

## 2. Related Work

- **LLM agent security:** InjecAgent (Tsinghua, 2024), AgentDojo (ETH, 2024), AdvAgent (2024) -- all focus on single-agent prompt injection, not cross-agent composition
- **Tool-use safety:** ToolEmu (Stanford, 2024), TaskBench -- simulate tool risks but lack formal propagation model
- **Attack graphs & risk propagation:** Classical attack graphs (Sheyner 2002, Noel 2006) for network security; we adapt to LLM agent context
- **Multi-agent verification:** Process algebra approaches (CSP, CCS) for concurrent systems; not applied to LLM tool chains
- **Gap:** No work formally models how risk accumulates, attenuates, and propagates across multi-agent tool chains

## 3. Methodology

### 3.1 Threat Model
- Adversary controls: malicious prompts, compromised tools, adversarial agent configurations
- Goal: detect when a sequence of individually-safe actions produces an unsafe outcome
- Scope: DAG-structured agent workflows (no cycles for formal tractability)

### 3.2 Behavior Chain Graph (BCG)
- **Nodes:** (agent_id, tool_call, input_state, output_state)
- **Edges:** data_flow, control_flow, dependency
- **Construction:** Runtime instrumentation intercepts tool calls, builds BCG incrementally

### 3.3 Risk Propagation Model
- **Base risk:** Each node assigned risk score r(v) in [0, 1] via classifier
- **Propagation rule:** r(v) = max(local_risk(v), max_{u in parents(v)} f(r(u), edge_type))
- **Dynamic attenuation:** f(r, depth) = r * alpha^depth, where alpha in (0.5, 0.9) is attenuation factor
- **Compositional risk:** R(chain) = 1 - prod_{v in chain}(1 - r(v)) -- OR-semantic over chain
- **Threshold detection:** Alert if R(chain) > tau

### 3.4 Runtime Detection Algorithm
- Incremental BCG construction with windowed risk computation
- Amortized O(n log n) per tool call event
- Early termination when R(chain) < tau * beta (safe prefix pruning)

### 3.5 Mitigation Strategies
- Chain breaking: insert guard nodes at high-risk edges
- Dynamic attenuation tuning: adjust alpha based on context trust level
- Capability-based access control per chain segment

## 4. Experiments

### 4.1 Setup
- **Test cases:** 200 independently constructed scenarios (not generated by ChainRisk)
- **Attack categories (4):**
  1. Prompt injection chains (multi-hop injection across agents)
  2. Tool misuse cascades (benign tools composed to harmful effect)
  3. Data exfiltration paths (information flows to unauthorized sinks)
  4. Privilege escalation chains (capability accumulation across agents)
- **Baseline methods (6):**
  1. ReAct-style single-agent guard (prompt-level)
  2. ToolEmu-style simulation-based detection
  3. Static attack graph analysis
  4. Threshold-only risk scoring (no propagation)
  5. LLM-as-judge (GPT-4o based chain evaluation)
  6. Input/output filtering (Nemo Guardrails style)

### 4.2 Metrics
- Detection rate (TPR), False positive rate (FPR), F1 score
- Risk score accuracy vs. expert-labeled ground truth
- Runtime overhead (latency per tool call)

## 5. Discussion

- **Deployment:** Integration with existing agent frameworks (LangChain, CrewAI) via middleware; <5% latency overhead target
- **Adversarial robustness:** Attacker-aware evasion (hiding risk in long chains); discuss alpha manipulation
- **Trade-offs:** Higher attenuation (larger alpha) = more sensitive but more false positives
- **Limitations:**
  - Assumes DAG structure (no cycles)
  - Requires runtime instrumentation access
  - Risk classifier accuracy bounds overall performance
  - 200 cases may not cover all real-world patterns

---

## 6. Conclusion

- ChainRisk provides the first formal framework for compositional risk in multi-agent tool-use systems
- Behavior chain graphs + dynamic attenuation enable detection of emergent threats invisible to single-agent defenses
- Evaluated on 200 independent cases with 6 baselines; significant improvement in detection accuracy
- Future work: formal verification of BCG properties, real-time monitoring at scale, extension to cyclic workflows
