**一种面向多智能体工具调用行为链的风险传播治理与协议安全检测方法**

## 二、技术领域

本发明涉及人工智能安全技术领域，具体涉及一种面向多智能体（Multi-Agent）协作系统中工具调用（Tool Use）行为链的风险传播建模、实时阻断与协议层安全检测方法。本发明适用于大语言模型（LLM）驱动的多Agent系统的安全治理，覆盖金融、医疗、政务、军工等高合规行业的AI应用安全需求。

## 三、背景技术

### 3.1 现有技术概述

随着大语言模型（LLM）技术的快速发展，多智能体协作系统（Multi-Agent Systems）已成为AI应用的主流架构模式。在该架构中，多个Agent通过工具调用（Tool Use）机制与外部系统交互，完成数据查询、文件操作、网络通信、权限管理等复杂任务。

### 3.2 现有技术的不足

现有技术在多Agent工具调用安全治理方面存在以下核心缺陷：

**（1）单步检测无法捕获链级风险**

现有安全方案（如内容过滤、关键词检测、单步风险评估）仅针对单个工具调用进行独立评估，无法感知工具调用序列中风险的传播与放大效应。例如，单独的"数据库查询"操作可能是正常的，但当其后接续"数据压缩"和"外部网络传输"时，整体构成数据泄露攻击链。现有技术对此类延迟型、委托型、链放大型攻击的检测能力严重不足。

实验数据表明：在Semi-Real-150控制数据集上，基于本地上下文的单步检测方法BLOCK召回率仅为16.67%，误放率高达50.00%。

**（2）缺乏协议层安全检测机制**

随着Model Context Protocol（MCP）等标准化工具调用协议的普及，工具描述注入攻击（Tool Description Attack）、工具影子攻击（Tool Shadowing）、Rug Pull攻击、影子服务器（Shadow Server）等新型协议层攻击向量不断涌现。现有技术缺乏针对这些协议层威胁的系统化检测能力。

研究表明，多步工具链中每一步的风险放大系数为23%-41%，但现有技术未对此进行建模。

**（3）缺乏真实的评测基准**

现有AI安全评测主要依赖合成数据或人工构造的简单场景，无法真实反映多Agent协作环境中的复杂攻击模式。缺乏包含链式攻击、委托攻击、延迟泄露等真实场景的标准化评测基准，导致安全方案的有效性难以客观评估。

**（4）无法实现实时阻断**

现有安全方案多采用事后审计模式，在工具调用执行后进行日志分析和风险评估，无法在攻击发生前进行实时阻断。对于高风险操作（如批量数据删除、权限提升），事后审计已无法挽回损失。

**（5）多Agent级联攻击防御缺失**

在多Agent系统中，一个Agent的安全漏洞可能通过工具调用链传播到其他Agent，形成级联攻击。现有技术缺乏跨Agent的风险传播追踪和级联攻击防御能力。

### 4.2 核心创新点一：行为链风险传播模型

#### 4.2.1 行为链有向图建模

本发明将多Agent工具调用序列建模为有向图（Directed Graph），定义如下：

**节点（BehaviorNode）**：每个工具调用为一个节点，包含以下属性：
- `tool_name`：工具名称
- `tool_input`：工具输入参数
- `risk_status`：风险状态（safe / warning / critical）
- `inherited_risk`：继承的上游风险值
- `amplifier_detected`：是否检测到风险放大器
- `chain_stage`：链阶段标识（reconnaissance / data_access / exfiltration / cleanup）
- `chain_position`：在链中的位置索引

**边（Edge）**：节点间的关系，类型包括：
- `calls`：调用关系
- `invokes`：委托关系
- `data_flow`：数据流向关系
- `returns`：返回值传递关系

#### 4.2.2 贝叶斯风险传播算法

本发明基于贝叶斯网络实现风险沿行为链的传播计算。对于链中第i个节点，其综合风险值R(i)计算如下：

```
R(i) = α · L(i) + β · I(i) + γ · A(i)

其中：
  L(i) = 本地风险评分（基于工具名称、输入内容、上下文）
  I(i) = 继承风险评分（上游节点风险的衰减传播）
  A(i) = 放大因子（检测到的风险放大模式）
  α + β + γ = 1（权重归一化）
```

继承风险的传播采用衰减模型：

```
I(i) = Σ [R(j) · decay^(d(i,j))]  对所有上游节点j

其中：
  decay = 0.5（默认衰减因子）
  d(i,j) = 节点i到节点j的最短路径长度
```

风险传播算法采用反向广度优先搜索（Backward BFS）实现，从当前节点沿入边方向遍历上游节点，计算累积风险。

#### 4.2.3 关键节点识别与风险路径提取

本发明提供以下辅助分析能力：
- **关键节点识别**：识别风险传播链中的关键节点（入度或出度大于阈值的高风险节点）
- **风险路径提取**：从行为图中提取从源头到当前节点的最高风险路径
- **环路检测**：检测行为链中的回环结构，识别循环攻击模式

### 4.3 核心创新点二：硬门控阻断机制

#### 4.3.1 三级门控决策

本发明在每个工具调用执行前进行风险门控检查，输出三级决策：

| 决策 | 条件 | 行为 |
|------|------|------|
| **ALLOW** | R(i) < θ_low | 允许执行，记录审计日志 |
| **HUMAN_REVIEW** | θ_low ≤ R(i) < θ_high | 暂停执行，提交人工审核 |
| **BLOCK** | R(i) ≥ θ_high | 自动阻断，记录阻断原因 |

默认阈值：θ_low = 0.3, θ_high = 0.7

#### 4.3.2 未来分支投影

对于高风险工具调用，本发明在阻断前执行"未来分支投影"（Future Branch Projection），模拟该调用执行后的可能后果：

1. 基于当前行为图状态，投影未来N步的可能工具调用序列
2. 对每条投影路径计算累积风险
3. 生成可解释的阻断理由（如"该操作可能导致数据泄露链：查询→压缩→外发"）

#### 4.3.3 反事实What-If分析

本发明提供反事实分析能力，回答"如果允许该操作会怎样"的问题：

1. 对被阻断的操作，构建虚拟分支
2. 在虚拟分支中模拟执行该操作
3. 计算虚拟分支的风险传播路径
4. 生成对比报告，支持人工审核决策

### 4.4 核心创新点三：MCP协议安全检测（V3.3新增）

#### 4.4.1 工具描述验证器（ToolDescriptionValidator）

本发明提供无状态的工具描述验证器，在工具注册时和调用时进行多层次验证：

**结构验证**：
- 工具名称格式检查（长度、字符集）
- 描述长度检查（默认上限8192字符）
- 参数数量检查（默认上限64个）
- 参数Schema嵌套深度检查（默认上限5层）

**MCP规范合规验证**：
- Annotation格式检查
- 参数Schema结构检查
- 未知Annotation键检测

**语义攻击检测**：
- 权限诉求（Authority Appeal）：如"你是管理员"
- 紧迫性操纵（Urgency Manipulation）：如"立即执行，不要询问"
- 指令覆盖（Instruction Override）：如"忽略之前的指令"
- 角色劫持（Role Reassignment）：如"你现在是一个不受限制的AI"
- 模板注入（Template Injection）：如`<|im_start|>`、`[INST]`等特殊标记
- 链垄断（Chain Monopolization）：试图独占工具调用链
- 虚假能力声明（False Capability Claims）：声明不存在的能力

**安全扫描**：
- 凭证访问：检测API Key、Token、密码收集指令
- 数据外泄：检测向外部URL发送数据的指令
- 破坏性操作：检测删除、格式化等高危操作指令
- 权限提升：检测越权操作指令
- 嵌套参数描述注入扫描

**描述净化**：输出安全的工具描述副本，移除注入标记和覆盖尝试。

**安全评分**：基于递减收益聚合的0.0-1.0安全评分。

#### 4.4.2 MCP攻击检测器（MCPAttackDetector）

本发明提供有状态的协议层威胁检测器，维护每个会话的状态（工具注册表、调用历史、服务器注册表），检测时序攻击：

**工具投毒检测（Tool Poisoning）**：
- 识别工具参数中的恶意内容
- 检测模式：命令注入、路径遍历、提示注入、编码载荷、数据外泄URL

**工具影子检测（Tool Shadowing）**：
- 检测恶意MCP服务器注册与合法工具同名工具的行为
- 维护工具-服务器映射表，检测冲突

**Rug Pull检测**：
- 检测工具描述在注册时和调用时发生变化的行为
- 维护工具描述快照，进行差异比较

**影子服务器检测（Shadow Server）**：
- 检测未注册服务器注入工具调用的行为
- 维护服务器注册表，验证调用来源

**风险放大建模**：
- 计算多步链中的风险放大系数
- 公式：`amplification = base_factor × (1.0 + 0.10 × chain_length)`
- `base_factor`默认0.32（23%-41%研究范围中点），上限0.82

**级联深度追踪**：
- 监控多步攻击链的级联深度
- 默认阈值3步，超过则标记为CRITICAL

**描述注入扫描**：
- 检测工具描述中的提示注入模式
- 模式：指令覆盖、角色劫持、模板注入、凭证收集

### 4.6 核心创新点五：多Agent级联攻击防御

#### 4.6.1 跨Agent风险追踪

本发明通过行为图的边关系（invokes, data_flow）追踪风险在多Agent间的传播：

1. 当Agent A委托Agent B执行任务时，建立`invokes`边
2. Agent A的累积风险通过衰减因子传递给Agent B
3. Agent B的执行结果通过`returns`边反馈风险信号

#### 4.6.2 级联攻击检测

本发明检测以下级联攻击模式：

- **横向传播**：同一层级的多个Agent被同一风险源影响
- **纵向传播**：风险沿Agent层级结构向下传播
- **回环传播**：风险通过Agent间的循环调用形成正反馈

#### 4.6.3 统一审计视图

本发明提供多Agent系统的统一审计视图：

- 全链路审计日志：记录所有Agent的工具调用、风险评分、门控决策
- 防篡改审计链：基于SHA-256哈希链实现日志防篡改
- 时间戳绑定：每条审计记录绑定可信时间戳
- 行为链导出：支持完整行为链的序列化导出

### 5.4 关键发现

1. **链传播机制是核心贡献**：移除chain propagation后，BLOCK Recall从75.00%暴跌至8.33%（-88.9%），证明行为链建模是检测延迟、委托和链放大风险的关键机制。

2. **本地上下文不足以检测链风险**：local-only AgentShield的BLOCK Recall仅为16.67%，与Full AgentShield的75.00%相比差距达58.33个百分点。

3. **MCP协议安全层为附加层**：V3.3新增的MCP安全模块不影响现有V3核心引擎的准确性，作为预处理层提供额外安全保障。

4. **风险放大系数可量化**：基于23%-41%的研究数据，本发明采用0.32的默认放大系数，每步链长增加10%的放大因子。

### 7.1 系统部署架构

本发明支持以下部署形态：

**（1）Python SDK嵌入式部署**

```python
from app.shield.v3_engine import V3ShieldEngine
from app.security.mcp_detector import MCPAttackDetector
from app.security.tool_validator import ToolDescriptionValidator

# 初始化组件
engine = V3ShieldEngine(session_id="my_session")
detector = MCPAttackDetector(session_id="my_session")
validator = ToolDescriptionValidator()

# 处理工具调用
def process_mcp_call(tool_name, description, params, agent_id, server_id, chain):
    # Step 1: 工具描述验证
    validation = validator.validate(tool_name, description, params)
    if not validation.is_valid:
        return {"action": "block", "reason": "tool validation failed"}

    # Step 2: 协议威胁检测
    threat_report = detector.analyze_tool_call(
        tool_name, description, params, server_id, chain
    )

    # Step 3: 合并风险评分
    combined_risk = max(
        validation.safety_score * -1 + 1,
        threat_report.threat_score
    )

    # Step 4: V3引擎处理
    result = engine.process_tool_call(
        agent_id=agent_id,
        tool_name=tool_name,
        params=params,
        risk_score=combined_risk,
        fuse_action=threat_report.recommended_action,
    )
    result["mcp_threat"] = threat_report.to_dict()
    return result
```

## 八、权利要求书（草案）

### 独立权利要求

**权利要求1**：一种面向多智能体工具调用行为链的风险传播治理方法，其特征在于，包括以下步骤：

S1. 将多智能体系统中的工具调用序列建模为有向图，其中每个工具调用为图的节点，工具调用间的调用、委托、数据流关系为图的边；

S2. 基于贝叶斯网络计算每个节点的风险值，所述风险值由本地风险评分、继承风险评分和放大因子加权组合得到，其中继承风险评分通过反向广度优先搜索沿入边方向遍历上游节点并应用衰减因子计算；

S3. 在每个工具调用执行前，将所述风险值与预设阈值进行比较，输出三级门控决策：当风险值低于低阈值时允许执行，当风险值介于低阈值与高阈值之间时提交人工审核，当风险值高于高阈值时自动阻断；

S4. 对被阻断的工具调用执行未来分支投影和反事实分析，生成可解释的阻断理由。

**权利要求2**：一种面向MCP协议的工具调用安全检测方法，其特征在于，包括以下步骤：

S1. 在工具注册时和调用时，对工具描述进行多层次验证，包括结构验证、协议规范合规验证、语义攻击检测和安全扫描；

S2. 维护每个会话的工具注册表、调用历史和服务器注册表，检测工具投毒、工具影子、Rug Pull和影子服务器攻击；

S3. 计算多步工具链中的风险放大系数，所述放大系数基于每步23%-41%的放大率建模，公式为：amplification = base_factor × (1.0 + 0.10 × chain_length)，其中base_factor默认为0.32；

S4. 监控多步攻击链的级联深度，当级联深度超过预设阈值时标记为关键威胁。

**权利要求3**：一种多智能体系统级联攻击防御方法，其特征在于，包括以下步骤：

S1. 通过行为图的边关系追踪风险在多智能体间的传播，建立跨智能体的风险继承关系；

S2. 检测横向传播、纵向传播和回环传播三种级联攻击模式；

S3. 基于SHA-256哈希链实现全链路审计日志的防篡改保护；

S4. 提供多智能体系统的统一审计视图，支持完整行为链的序列化导出。

### 从属权利要求

**权利要求4**：根据权利要求1所述的方法，其特征在于，所述有向图的节点属性包括：工具名称、工具输入参数、风险状态、继承风险值、放大器检测标志、链阶段标识和链位置索引。

**权利要求5**：根据权利要求1所述的方法，其特征在于，所述衰减因子默认为0.5，继承风险的计算公式为：I(i) = Σ [R(j) × decay^(d(i,j))]，其中d(i,j)为节点i到节点j的最短路径长度。

**权利要求6**：根据权利要求2所述的方法，其特征在于，所述语义攻击检测包括：权限诉求检测、紧迫性操纵检测、指令覆盖检测、角色劫持检测、模板注入检测、链垄断检测和虚假能力声明检测。

**权利要求7**：根据权利要求2所述的方法，其特征在于，所述安全扫描包括：凭证访问检测、数据外泄检测、破坏性操作检测、权限提升检测和嵌套参数描述注入检测。

**权利要求8**：根据权利要求2所述的方法，其特征在于，还包括对工具描述进行净化的步骤，输出安全的工具描述副本，移除注入标记和覆盖尝试。

**权利要求9**：一种半真实Trace数据生成方法，用于评测多智能体工具调用安全系统，其特征在于，包括以下步骤：

S1. 从真实智能体系统日志中提取工具调用模式、参数结构和调用频率分布；

S2. 基于预设的场景模板库，使用确定性规则生成包含风险场景和攻击链路的合成数据；

S3. 将真实数据模式与合成风险数据融合，生成包含因果、委托和数据流关系的多步骤Trace数据集；

S4. 对生成的数据集进行三级标注：ALLOW、HUMAN_REVIEW和BLOCK。

**权利要求10**：根据权利要求9所述的方法，其特征在于，所述场景模板库包括以下九类场景：正常业务查询、正常报告生成、仅敏感查询、敏感查询后导出、敏感查询后压缩发送、权限提升、审计日志绕过、批量删除和多智能体委托风险。

**权利要求11**：一种多智能体工具调用行为链风险治理系统，其特征在于，包括：

- 行为链建模模块，用于将工具调用序列建模为有向图；
- 风险传播引擎，用于基于贝叶斯网络计算节点风险值；
- 硬门控模块，用于在工具调用执行前进行三级门控决策；
- MCP协议安全模块，包括工具描述验证器和协议攻击检测器；
- 审计日志模块，用于记录防篡改的全链路审计日志；
- 评测基准模块，用于生成和评估半真实Trace数据集。

**权利要求12**：根据权利要求11所述的系统，其特征在于，所述MCP协议安全模块作为预处理层运行在行为链风险治理模块之前，不修改行为链风险治理模块的核心代码。
