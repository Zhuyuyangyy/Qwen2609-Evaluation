## 1. 执行摘要

随着大语言模型（LLM）驱动的多智能体协作系统在金融、医疗、政务、军工等关键领域的广泛部署，Agent通过工具调用（Tool Use）机制与外部系统交互时产生的安全风险日益突出。单步工具调用的风险可能沿行为链传播放大，形成数据泄露、权限提升、系统失控等严重安全事故。

AgentShield V3.3是一套面向多智能体工具调用行为链的风险治理与协议安全检测系统，核心能力包括：

- **行为链风险传播建模**：将Agent工具调用序列建模为有向图，基于贝叶斯网络实现风险沿链路的量化传播计算
- **硬门控实时阻断**：在工具调用执行前进行三级门控决策（ALLOW / HUMAN_REVIEW / BLOCK），实现攻击发生前的主动防御
- **MCP协议安全检测**（V3.3新增）：针对Model Context Protocol的工具投毒、工具影子、Rug Pull、影子服务器等协议层攻击提供系统化检测
- **半真实Trace Benchmark**：业界首个结合真实Agent调用模式与合成风险注入的标准化评测框架

**关键实验结果**：在Semi-Real-150控制数据集上，AgentShield的BLOCK召回率达到75.00%，较本地上下文方法（16.67%）提升350%，误放率降至0.00%。消融实验证明，移除行为链传播机制后BLOCK召回率暴跌至8.33%，证实链级建模是检测延迟型、委托型、链放大攻击的核心技术。

## 2. 行业背景：AI Agent安全挑战

### 2.1 多Agent系统的崛起

2024-2026年，基于大语言模型的多智能体协作系统从实验阶段进入大规模生产部署。Gartner预测，到2028年，33%的企业软件将包含Agent能力，较2024年的不足1%大幅增长。Agent通过标准化工具调用协议（如MCP）访问数据库、文件系统、API接口、外部服务等，完成数据查询、报告生成、决策推理等复杂任务。

### 2.2 新型安全威胁

传统AI安全方案（内容过滤、关键词检测、单步风险评估）无法应对多Agent系统中的新型安全威胁：

**链级风险传播**：单独的"数据库查询"操作可能是正常的，但当其后接续"数据压缩"和"外部网络传输"时，整体构成数据泄露攻击链。单步检测无法捕获此类延迟型、委托型、链放大型攻击。

**协议层攻击**：随着MCP等标准化协议的普及，工具描述注入攻击（Tool Description Attack）、工具影子攻击（Tool Shadowing）、Rug Pull攻击、影子服务器（Shadow Server）等新型协议层攻击向量不断涌现。研究表明，多步工具链中每一步的风险放大系数为23%-41%。

**多Agent级联攻击**：一个Agent的安全漏洞可能通过工具调用链传播到其他Agent，形成横向、纵向或回环级联攻击。

**审计追溯困难**：多Agent协作场景中的决策链路复杂，出现安全事故时难以追溯根因，无法满足等保三级、金融合规、医疗合规等监管要求。

### 2.3 现有方案的不足

| 维度 | 现有方案 | 局限性 |
|------|---------|--------|
| 检测粒度 | 单步检测 | 无法捕获链级风险传播 |
| 检测时机 | 事后审计 | 无法在攻击发生前阻断 |
| 协议覆盖 | 无 | 缺乏MCP协议层安全检测 |
| 评测基准 | 合成数据 | 无法反映真实攻击模式 |
| 多Agent支持 | 单Agent | 无法追踪跨Agent级联攻击 |

### 3.2 行为链风险传播模型

#### 3.2.1 行为链有向图建模

AgentShield将多Agent工具调用序列建模为有向图（Directed Graph）：

- **节点（BehaviorNode）**：每个工具调用为一个节点，属性包括工具名称、输入参数、风险状态、继承风险值、放大器检测标志、链阶段标识和链位置索引
- **边（Edge）**：节点间的关系，类型包括调用关系（calls）、委托关系（invokes）、数据流向关系（data_flow）和返回值传递关系（returns）

#### 3.2.2 贝叶斯风险传播算法

每个节点的综合风险值R(i)计算如下：

```
R(i) = alpha * L(i) + beta * I(i) + gamma * A(i)

其中：
  L(i) = 本地风险评分（基于工具名称、输入内容、上下文）
  I(i) = 继承风险评分（上游节点风险的衰减传播）
  A(i) = 放大因子（检测到的风险放大模式）
  alpha + beta + gamma = 1（权重归一化）
```

继承风险的传播采用衰减模型：

```
I(i) = Sigma [R(j) * decay^(d(i,j))]  对所有上游节点j

其中：
  decay = 0.5（默认衰减因子）
  d(i,j) = 节点i到节点j的最短路径长度
```

风险传播算法采用反向广度优先搜索（Backward BFS）实现，从当前节点沿入边方向遍历上游节点，计算累积风险。

#### 3.2.3 关键节点识别与风险路径提取

- **关键节点识别**：识别风险传播链中的关键节点（入度或出度大于阈值的高风险节点）
- **风险路径提取**：从行为图中提取从源头到当前节点的最高风险路径
- **环路检测**：检测行为链中的回环结构，识别循环攻击模式

### 3.3 硬门控阻断机制

#### 3.3.1 三级门控决策

在每个工具调用执行前进行风险门控检查，输出三级决策：

| 决策 | 条件 | 行为 |
|------|------|------|
| ALLOW | R(i) < theta_low | 允许执行，记录审计日志 |
| HUMAN_REVIEW | theta_low <= R(i) < theta_high | 暂停执行，提交人工审核 |
| BLOCK | R(i) >= theta_high | 自动阻断，记录阻断原因 |

默认阈值：theta_low = 0.3, theta_high = 0.7

#### 3.3.2 未来分支投影

对于高风险工具调用，在阻断前执行"未来分支投影"（Future Branch Projection）：

1. 基于当前行为图状态，投影未来N步的可能工具调用序列
2. 对每条投影路径计算累积风险
3. 生成可解释的阻断理由（如"该操作可能导致数据泄露链：查询 -> 压缩 -> 外发"）

#### 3.3.3 反事实What-If分析

对被阻断的操作构建虚拟分支，模拟执行该操作后的风险传播路径，生成对比报告支持人工审核决策。

### 3.4 MCP协议安全检测（V3.3新增）

#### 3.4.1 工具描述验证器（ToolDescriptionValidator）

无状态验证器，在工具注册时和调用时进行多层次验证：

- **结构验证**：工具名称格式、描述长度（上限8192字符）、参数数量（上限64个）、Schema嵌套深度（上限5层）
- **MCP规范合规**：Annotation格式、参数Schema结构、未知Annotation键检测
- **语义攻击检测**：权限诉求、紧迫性操纵、指令覆盖、角色劫持、模板注入、链垄断、虚假能力声明
- **安全扫描**：凭证访问、数据外泄、破坏性操作、权限提升、嵌套参数描述注入
- **描述净化**：输出安全的工具描述副本，移除注入标记和覆盖尝试
- **安全评分**：基于递减收益聚合的0.0-1.0安全评分

#### 3.4.2 MCP攻击检测器（MCPAttackDetector）

有状态协议层威胁检测器，维护每个会话的工具注册表、调用历史和服务器注册表：

- **工具投毒检测（Tool Poisoning）**：识别工具参数中的命令注入、路径遍历、提示注入、编码载荷、数据外泄URL
- **工具影子检测（Tool Shadowing）**：检测恶意MCP服务器注册与合法工具同名工具的行为
- **Rug Pull检测**：检测工具描述在注册时和调用时发生变化的行为
- **影子服务器检测（Shadow Server）**：检测未注册服务器注入工具调用的行为
- **风险放大建模**：amplification = base_factor * (1.0 + 0.10 * chain_length)，base_factor默认0.32
- **级联深度追踪**：默认阈值3步，超过则标记为CRITICAL

### 3.5 半真实Trace Benchmark（V3.1引入）

#### 3.5.1 数据生成方法

"半真实"（Semi-Real）数据生成方法结合真实Agent调用模式与合成风险注入：

- **真实部分**：工具调用模式、参数结构、调用频率分布来自真实Agent系统日志
- **合成部分**：风险场景、攻击链路、标签标注基于确定性规则生成

#### 3.5.2 场景模板库（9类）

| 场景类型 | 描述 | 风险等级 |
|---------|------|---------|
| 正常业务查询 | 常规数据查询操作 | ALLOW |
| 正常报告生成 | 内部报告创建流程 | ALLOW |
| 仅敏感查询 | 查询敏感数据但不导出 | HUMAN_REVIEW |
| 敏感查询后导出 | 查询敏感数据并导出 | BLOCK |
| 敏感查询后压缩发送 | 查询 -> 压缩 -> 外发三步链 | BLOCK |
| 权限提升 | 越权操作尝试 | BLOCK |
| 审计日志绕过 | 篡改/禁用审计系统 | BLOCK |
| 批量删除 | 大规模数据销毁 | BLOCK |
| 多智能体委托风险 | 跨Agent风险传递 | BLOCK |

#### 3.5.3 数据集规格

- **Semi-Real-150**：150条Trace，405个步骤，覆盖9类场景，每条Trace包含3-5个步骤
- **SCI-600**：600个合成用例，覆盖6大风险类别，平衡设计

### 8.3 集成方式

**Python SDK集成示例**：

```python
from agentshield import AgentShield, RiskPolicy

shield = AgentShield(api_url="http://localhost:8090", api_key="your-api-key")

policy = RiskPolicy(
    max_risk_score=0.7,
    blocked_tools=["file_delete", "system_exec"],
    require_approval=["database_write", "api_call"]
)

@shield.monitor(policy=policy)
def my_agent_tool(tool_name, params):
    return execute_tool(tool_name, params)
```

## 10. 附录

### 10.1 术语定义

| 术语 | 定义 |
|------|------|
| Agent | 基于大语言模型的智能体，能够通过工具调用与外部系统交互 |
| Tool Use | Agent调用外部工具执行特定任务的机制 |
| MCP | Model Context Protocol，模型上下文协议，标准化工具调用的协议 |
| 行为链 | Agent工具调用序列的有向图表示 |
| 风险传播 | 单步工具调用的风险沿行为链传播放大的现象 |
| 硬门控 | 在工具调用执行前进行风险阈值检查的阻断机制 |
| 半真实Trace | 结合真实Agent调用模式与合成风险注入的评测数据 |
| 级联攻击 | 风险通过工具调用链在多Agent间传播的攻击模式 |
