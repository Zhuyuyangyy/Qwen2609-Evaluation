# Experience-Shaped Affective Agent V0.8 Specification

## Overview

Experience-Shaped Affective Agent is a model-agnostic framework for emotion-like behavioral modulation. The system does NOT claim to have subjective emotions, but implements functional mechanisms inspired by affective psychology.

## Core Proposition

> Emotion is not output tone, but a persistent shaping mechanism where experiences modify future behavior.

## Version History

### V0.1: Emotional State & Experience Memory
- EmotionalState: Core emotional state representation (valence, arousal, category)
- ExperienceMemory: Experience storage with emotional tagging

### V0.2: Affect Regulation
- AffectRegulation: Self-regulation mechanisms
- Energy management and emotional self-control

### V0.3: Affective Generalization
- EventSimilarity: Event similarity based on handcrafted features
- AffectiveSpread: Emotional influence propagation to similar events
- SemanticRiskMap: Risk prediction based on semantic similarity

### V0.4: Conflict & Hesitation
- ConflictDetector: Detection of reward-risk conflicts
- HesitationPolicy: Generation of intermediate hesitation actions
- CounterfactualSimulator: What-if analysis and risk explanation

### V0.5: LLM Integration
- MockOpenAIProvider: Mock LLM provider for testing
- PromptModulator: Affective state injection into prompts
- LLMOutputGuard: Output validation and sanitization
- LLMPlanner: Integrated LLM planning with affective modulation

### V0.6: Benchmark
- AffectiveBenchmark: 100-task evaluation suite
- 4 Baselines: Plain, Memory-only, Risk-rule, Full Affective
- 6 Metrics: Risky Auto-Exec, Verification, Trust Error, Recovery, Gen Precision, False Caution

### V0.7: Phoenix-Evo/AgentShield Integration
- PhoenixIntegration: Phoenix-Evo experience signal processing

### V0.8: Complete System Integration
- All modules integrated

- Full test coverage

## Innovation Points

1. **Cognitive Appraisal Vector**: Multi-dimensional consequence evaluation
2. **Interoceptive Self-State**: Persistent self-state as planning bias
3. **Affective Memory**: Severity-weighted experience storage
4. **Stimulus Generalization**: Emotional spread to similar events
5. **Strategy Modulation**: Emotion as policy parameter modifier
6. **Recovery Dynamics**: Evidence-based state recovery
7. **Hesitation Behavior**: Observable intermediate actions
8. **Model-Agnostic Shell**: Works with any LLM/Agent

## Architecture

```
Experience Event
    ↓
Consequence Evaluation (Cognitive Appraisal)
    ↓
Self-State Update (Interoceptive State)
    ↓
Affective Memory Write (Emotion-Weighted)
    ↓
Policy Modulation (Strategy Adjustment)
    ↓
Behavioral Decision (Action Selection)
```

## Key Principles

1. No subjective emotion claims
2. Model-agnostic design
3. Deterministic testing (all mocks)
4. Observable behavioral effects
5. Quantifiable metrics

## Usage

```python
from emotion_agent import AffectiveAgent

agent = AffectiveAgent()
agent.perceive("delete important file")
agent.feel(category="fear", intensity=0.8)
response = agent.respond()
```

## Limitations

- This system does NOT have subjective emotions
- All "emotion-like" states are functional representations
- Behavior changes are based on rules, not feelings
